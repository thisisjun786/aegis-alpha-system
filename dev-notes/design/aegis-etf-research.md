# 이지스 ETF 연구 실행 계획

이지스는 ETF를 투자 대상으로 삼는다. 원본 전략과 시장 자료를 내장 DB에 보관하는 단계에서,
출처를 고정한 입력으로 체결·비용·성과를 계산하는 단계로 연결한다. 이 문서는 구현 순서를
정하며, 실제 실행 가능 여부는 [현재 아키텍처](../architecture.md)의 진입점 표를 따른다.

## 원본 전략 재현이 먼저다

원본 레시피와 기준 성과는 비공개 저장소에 보존한다. 공통 엔진은 명시적으로 받은 가격,
거래일, 목표 비중과 비용을 사용한다. 신호일 종가로 결정한 비중은 다음 실제 거래일 시가에
체결하고, 매수·매도 비용과 잔여 현금을 원장에 반영한다. 누락된 시가를 종가로 대체하지 않는다.

전략별 결과는 실행 여부, 입력 기간, 사용한 데이터·코드 해시, 지원하지 않는 규칙과 비교
조건을 남긴다. 기존 결과 파일의 존재는 새 엔진의 실행 증거가 아니다. 원본 시스템과의
일치, 명시한 경제 규칙의 계산, 체결 검증과 시점 적합성은 각각 판정한다.

정규화한 연구 조건으로 이전 성과를 재현해도 원본 전략 재현이 끝난 것은 아니다.
원본의 정기 납입금, 지정 체결일, 휴일 처리와 비용 단위를 따로 대조한다. 납입금이 있는
계좌 가치는 투자 수익률과 구분하며, 원본 규칙이 불명확하면 그 항목은 미검증으로 남긴다.

클라이언트 요청에서 확인한 필드는 서버 계산식을 입증하지 않는다. 고점의 기준, 조회 기간,
고점 초기화와 재진입 규칙이 불명확하면 원본 의미는 미검증으로 남긴다. 별도로 명시한
가정으로 실행하는 연구 시나리오는 새 식별자를 부여하고 원본 설정과 결과를 보존한다.

기존 검증은 입력·코드·판정 기준이 같을 때 재사용한다. 뒤늦게 추가한 비교나 독립 리뷰는
기존 명세의 해시를 참조하는 새 증거로 연결하며, 과거 명세를 고쳐 당시 검증에 포함됐다고
기록하지 않는다. 별도 시나리오의 실행 성공은 원본 기준 결과를 바꾸지 않으며, 전체 전략
통합 결과에 반영하기 전에는 독립 검토와 저장 결과 확인이 필요하다.

## 내장 DB에 연결한 뒤 데이터를 갱신한다

원본 자료실은 저장된 값을 보존하는 계층이다. 실행 입력은 종목 식별, 가격 조정 기준,
통화, 거래 달력과 사용 가능 시각을 추가로 확인해야 한다. 이미 받은 원본을 먼저 검증하고
필요한 구간만 수집한다. Qveris 경로와 실제 공급자를 모두 기록하며 기존 가격을 덮어쓰지 않는다.

일일 작업은 호출 전 사용량을 예약하고, 받은 응답과 완료 기록을 보존한다. 요금 정산이나
호출 성공 여부가 불확실하면 유료 재호출을 자동 반복하지 않는다. 수집 한도에 걸린 작업은
누락 상태와 다음 재개 위치를 유지한다. 타이머 활성화와 실제 내장 DB 반영은 별도로 검증한다.

## 상장 전 프록시는 별도 연구 자료다

지수나 현물 시계열은 ETF 상장 전 신호와 가상 수익률 연구에 사용할 수 있다. 실제 ETF
가격과 분리하고, 수익률을 연결한 계산식·전환일·통화·배당·수수료 가정을 기록한다. 프록시로
존재하지 않았던 ETF의 시가나 거래량을 만들지 않는다. 실제 ETF 체결에는 상장일과 관측
가격이 필요하다. 혼합시장 계산은 환율과 시장별 의사결정·체결 시각을 검증해야 한다.

운용사나 지수의 설명서를 확보한 상태와 실제 과거 수익률을 확보한 상태는 구분한다.
후보별로 관측 시작일, 원본 해시, 수익률 기준과 접근 제한을 기록한다. 같은 날짜의 값도
발표 시각이나 거래 달력이 다를 수 있으므로 날짜 일치나 높은 상관관계만으로 연결하지 않는다.
자료가 없다는 판단에는 확인한 제공처와 범위를 남기고, 전 세계에 자료가 없다고 단정하지 않는다.

## 새 전략과 ETF 교체 후보를 검증한다

원본 전략을 보존하면서 명시적인 모멘텀, 위험 제한, 비중 계산의 조합으로 연구 후보를
생성한다. 후보와 평가 기준을 먼저 고정하고 학습·검증·최종 평가 구간을 분리한다. 실패한
후보, 거래 비용과 전체 시도 횟수도 기록한다. 검증 구간을 반복 사용하면 그 사실을 남긴다.

ETF 교체 후보는 같은 목표 노출·통화·환헤지·레버리지 조건을 충족하는지 먼저 확인한다.
그다음 수수료, 같은 기간의 추적 성과와 유동성을 비교한다. 자료가 없으면 비용을 0으로
간주하지 않는다. 주기적인 탐색은 근거가 있는 후보 보고서를 만들며 정본 ETF나 실거래를
자동 변경하지 않는다.

## 구현 순서와 범위

범용 위험 계산·후보 평가·ETF 비교는 명시적 입력과 합성 자료로 먼저 구현할 수 있다.
프록시 조사나 자료 사용 승인이 끝나야만 이 계산 기능을 개발할 수 있는 것은 아니다.
다만 범용 함수의 검증과 실제 연구 완료는 구분한다. 실제 후보 실행에는 출처·비용·평가
구간이 고정된 입력이 필요하며, 정기 탐색에는 실제 비교 자료와 실행 영수증이 필요하다.
최종 통합 판정에는 미완료 프록시 조사와 데이터 기준도 그대로 포함한다.


1. 출처가 고정된 DB 읽기와 ETF 체결·비용 계산을 연결하고 원본 전략을 실행한다.
2. 필요한 데이터와 한국 자료를 검증·보충하고 내장 DB 일일 갱신을 연결한다.
3. 정본 ETF별 과거 프록시 가능성을 조사하고 별도 연구 시계열을 만든다.
4. 부족한 계산 기능과 재현 가능한 신규 전략 생성·검증을 추가한다.
5. 비교 가능한 ETF 후보를 주기적으로 탐색한다.
6. 전체 전략과 예약 작업을 다시 실행해 결과와 남은 공백을 확인한다.

알파·헷지 구현과 실주문은 이 계획의 범위 밖이다. 테스트에는 합성 자료를 쓰고 실제 전략
실행·공급자 호출 결과는 비공개 운영 증거로 보관한다. 기존 계약은
[데이터 기반 설계](backtest-data-foundation.md)와
[공개 엔진·비공개 전략 분리](../decisions/0011-public-engine-private-strategies.md)를 따른다.
