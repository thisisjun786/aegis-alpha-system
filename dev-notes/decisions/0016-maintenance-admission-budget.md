# 유지보수 명령의 호출자 소유 승인

`db verify`, `db backup`, `db restore`, `db run-install`은 호출자가 준 계산 할당 안에서만
자료를 Python으로 올린다. 이 결정은 그 경계를 고정한다. 검증 범위, 봉인, 정체성, 결측 의미는
바꾸지 않는다. 저장 기술은 [0014](0014-local-embedded-databases.md), 물리 계약은
[데이터 설계](../design/backtest-data-foundation.md)가 계속 소유한다.

## 불변식

각 검증 단계 S에 대해 `charge(S) + live(S) <= A`를 지킨다. `A`는 비DuckDB 허용량, 곧
계산 할당에서 DuckDB 몫을 뺀 값이다. `charge(S)`는 그 단계가 Python으로 올릴 양의 SQL 집계
추정이고, `live(S)`는 단계를 넘어 살아 있는 보유분이다. 전체 설치본의 논리 내용을 한 번에
합산하지 않는다. 단계는 순차적으로 돌며 각자 문서를 놓아주므로, 합산 방식은 한 번에 하나씩
검증되는 정상 설치본을 근거 없이 거부한다.

DuckDB 쪽 작업은 같은 할당에서 유도한 연결 한도로 따로 묶는다. 이미 더 낮은 한도가 걸려
있으면 올리지 않는다.

## 승인은 읽기보다 먼저 온다

모든 승인은 fetch와 복호화와 부호화 **이전에** 끝난다. 크기를 넘긴 자료는 잘린 성공이 아니라
`ComputeResourceError`로 거부한다. 승인 자체는 내용 인증이 아니다. 정확한 pin과 해시 대조는
기존 소유자가 그대로 맡는다.

가변 폭 값은 개수가 아니라 바이트로 잰다. 보관 원본의 SQLite 컬럼은 `ANY`라 한 셀이 임의로
클 수 있으므로 셀 개수 기반 추정은 경계가 되지 못한다.

## 스트리밍 자료의 단위

보관 원본 테이블은 통째로 올리지 않는다. 기존 정규 배치 단위를 유지하고 **배치별 최대 과금**을
미리 잰다. 첫 배치만 재면 뒤쪽에 놓인 큰 값이 그대로 통과한다. 배치 경계는 `row_number`로
재현하며, 정수 나눗셈 연산자가 방언마다 다르다는 점을 반영한다. 기존 digest 형식과 배치 크기는
바꾸지 않는다.

## 확장 계수는 측정에서 나온다

부호화된 바이트에서 Python 객체로의 확장 계수는 추측하지 않고 측정해서 정한다. 측정은 보관된
history와 메타데이터가 살아 있는 상태에서 하고, Arrow 경로는 Python 힙 밖 할당까지 포함한다.
계수를 올리면 같은 할당에서 읽기 상한이 줄어드는 만큼, 영향을 받는 예산을 같은 변경에서
함께 조정하고 이유를 남긴다.

## 범위 밖

이 결정은 프로세스 RSS를 강제하지 않는다. 보수적인 자료화 승인이며 성능 보장도 아니다.
수집기와 공급자 호출, 비공개 자료, 실행 자격은 그대로 각자의 결정이 소유한다.
