# 외부 도구가 사용하는 데이터·연구 엔진

오너는 공개 문서와 제품 구조를 재검토하면서 AAS가 데이터와 연구 계산을 제공하고,
외부 앱이나 에이전트가 화면과 작업 진행을 맡는 방향을 선택했다. 이번 변경은 문서·설계
정리다. 기존 CLI, Python API, 저장 스키마나 세 모듈 입력 계약을 바꾸지 않는다.

## 책임

| 주체 | 책임 |
| --- | --- |
| AAS | 데이터 수집·저장·버전 및 시점 조회, 명시적 전략 입력의 검증·연구 계산, 결과와 출처 계약 |
| 외부 도구 | 사용자 화면, 연구 요청 구성, 작업 순서와 결과 표시 |
| 비공개 저장소 | 실제 전략 정의·자산·임계값·성과·보유 내역·공급자 키와 수집 데이터 |

이는 목표 책임을 정한 것이다. 현재 수집기는 legacy 저장 경로를 사용하며, 내장 데이터
조회에서 전략 실행과 결과 저장까지 이어지는 통합 경로는 미완성이다. 현재 기능과
진입점은 [구조](../architecture.md), 실행 명령은 [운영 안내](../operations.md)를 따른다.

## 기존 구조의 재검토

- **CLI 중심 독립 앱을 제품의 중심으로 유지**하면 설치와 직접 사용 흐름은 단순하지만,
  외부 도구가 재사용할 계산·데이터 경계가 제품 설명에서 가려진다. 제품의 중심은 엔진으로
  옮기고 CLI는 현재 지원하는 접근 수단으로 유지한다. 외부 플랫폼을 필수 의존성으로 추가하지 않는다.
- **계산만 제공**하면 경계는 작아지지만 수집·시점·출처·저장의 책임을 외부 도구마다
  다시 구현하게 된다. 오너가 선택한 데이터와 계산의 공동 소유에 맞춰 현재 저장 계약을 유지한다.
- **세 모듈을 모든 외부 호출의 필수 형식으로 확대**하지 않는다. Aegis·Alpha·Hedge는
  자산배분·종목 연구·방어 배분의 영역을 설명한다. 현재 `preview`는 여전히 세 모듈을 모두
  명시해야 하며, `engine.replay`의 명시적 입력 계산과 이 합성 계약은 서로 다른 진입점이다.
  장기 모듈/API 구조 변경은 별도 구현 설계에서 소비자와 호환성을 확인한다.
- **새 HTTP/MCP 서버를 먼저 만들지 않는다.** 현재 Python API와 CLI를 재사용할 수 있는지
  실제 소비자부터 확인한다. 원격 호출 방식·인증·취소·결과 조회는 아직 선택하지 않았다.

## 기존 결정의 적용 범위

[0009](0009-standalone-three-modules.md)의 CLI 중심 제품 설명은 이 결정으로 대체한다.
외부 실행 플랫폼 비필수, 세 모듈의 현재 계약, 포트폴리오 합성과 출처 고지 요구는 유지한다.
[0010](0010-backtest-data-foundation.md)의 데이터 의미,
[0011](0011-public-engine-private-strategies.md)의 공개·비공개 경계,
[0012](0012-retire-legacy-runtime.md)의 구버전 폐기,
[0014](0014-local-embedded-databases.md)의 로컬 내장 DB 선택도 유지한다.

[0013](0013-first-install-workspace.md)의 단일 소유 프로세스·로컬 소켓·같은 앱의 예약 실행은
승인됐지만 미구현인 설계로 남긴다. 외부 도구가 작업 순서를 맡는다는 결정이 이 설계를
이미 구현했거나 폐기했다는 뜻은 아니다. 향후 연결 시 외부 요청과 내부 실행의 책임을
확인하며, DB 파일을 외부 도구가 직접 공유해 여는 방식으로 우회하지 않는다.

## 결과와 후속 작업

현재 소스에는 `application/`의 CLI, `storage/`의 내장 DB 명령,
`engine/`의 명시적 입력 계산, `modules/`의 책임 선언이 있다. `strategy import`는 엔진
bundle 검증을 사용하지만 등록한 전략의 실행까지 연결하지 않는다. `preview` 역시 비중
합성만 수행한다. 명령이 존재하는 것과 공급자 호출·실제 데이터 복구·전체 백테스트 성공을 구분한다.

후속 구현은 [저장·실행 전환 표](../design/backtest-data-foundation.md#전환-계획과-기존-코드)가
소유한다. 데이터·전략 입력과 결과의 연결을 검증한 뒤 소비자용 인터페이스를 확정한다.
실주문·배포·공급자 활성화·실제 데이터 이전은 이 문서 정리에 포함하지 않는다.
