# src/aegis_alpha/metadata

## OVERVIEW
The retained PostgreSQL path for source snapshots, dataset versions, quality results, eligibility decisions, and feature contracts. Owns the shared SQLAlchemy `MetaData`, controlled installation and validated snapshot adoption. Native SQLite/DuckDB installation and catalog operations are owned by `storage/`; this package does not configure the default installation.

## WHERE TO LOOK
| Task | Module |
|------|--------|
| Register a snapshot / dataset / feature contract | `registry.py` (`MetadataRegistry`, ordinary registration owner) |
| Registration value types + credential rejection | `records.py` |
| Core tables (`public` + `engine` schemas) | `schema.py` |
| Eligibility decisions | `eligibility_schema.py` (has `__all__`) |
| Feature contracts and their inputs | `feature_contract_schema.py` (has `__all__`) |
| Engine construction / URL gate | `database.py` |

## CONVENTIONS
- `schema.py` defines the `MetaData` that `collection/schema.py`, `identity/schema.py`, and `data/canonical_generation_schema.py` all attach to; `migrations/env.py` imports these modules to populate Alembic's target metadata. A table not imported there is invisible to migrations.
- `_NAMING_CONVENTION` fixes constraint/index names (`ix_`, `uq_`, `ck_`, `fk_`, `pk_` + table + column). Never hand-name a constraint — autogenerated migration diffs depend on the convention.
- For this PostgreSQL path, `AAS_DATABASE_URL` is mandatory and must use the `postgresql+psycopg` driver; `load_database_url()` refuses anything else, including a valid PostgreSQL URL with a different driver. Engines are built with `pool_pre_ping=True` and a 5s connect timeout.
- Credential rejection is structural: `records.py` scans every metadata value and dict key at `__post_init__` (`_CREDENTIAL_VALUE_PATTERN`, `_is_credential_key`) and recursively through `freeze_json_metadata()`. Bearer tokens, URL credentials, and key-like keys raise instead of being redacted.
- Registrations are frozen dataclasses; JSON payloads are deep-copied and frozen before storage, so callers cannot mutate a persisted projection.
- Conflicts arrive as SQLAlchemy `IntegrityError` and are wrapped into domain errors — catch the domain error, do not inspect driver exceptions upstream.
- Constraints are duplicated deliberately: a SQL `CheckConstraint` *and* a Python validator. Change both or neither.

## ANTI-PATTERNS
- Ordinary registration uses `MetadataRegistry`. Controlled adoption uses `snapshot_import.py` and verifies original bytes, counts, generated columns and receipts in one transaction; do not bypass either owner.
- Never let credential-like text reach a metadata field "just to debug" — tests assert sentinel non-leakage across key and value forms.
- Never add a table without a matching Alembic revision; the test suite runs `alembic downgrade base` → `upgrade head` → `check` and destructive downgrades refuse unowned tables or leftover rows.

## COMMANDS
```bash
uv run --no-sync pytest tests/metadata            # requires the disposable PostgreSQL fixture
uv run --no-sync alembic check                    # migration/model drift
```
